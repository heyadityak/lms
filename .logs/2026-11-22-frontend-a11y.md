# 2026-11-22 frontend — axe contrast and sign-in redirect loop

## Goal

Fix the two Playwright smoke failures from commit c64ba1f if they were still on HEAD (`2902ecf`): serious color-contrast on `#dates_extra` at `/leave-requests/new`, and `ERR_TOO_MANY_REDIRECTS` on `/admin/settings/working-week` (same loop seen on `/leave-requests/new` after in-app login). Do not commit. Do not change audit-log, department, or location feature code.

## What I did

- Reproduced the loop on the compose stack: a `lms.session_token` cookie whose `session` row was gone still passed `web/src/proxy.ts` (`getSessionCookie` is presence only). `getMe` then rejected it (`getAccessToken` reads the database session) and redirected to `/signin`. The sign-in page treated `getSession` as signed-in (cookie cache) and redirected to `/`. Curl followed `/signin` ↔ `/` until the redirect limit.
- `web/src/lib/me.ts`: `loadMe()` returns the user only when the access token and `GET /me` both succeed, otherwise null. `getMe()` redirects to `/signin` when that is null. The sign-in page (`web/src/app/signin/page.tsx`) redirects home only when `loadMe()` returns a user. A cookie the proxy accepts but the API cannot use stays on the welcome form. `POST /bff/login` is unchanged. A real session still opens `/admin/settings/working-week` (carol, 200) and `/leave-requests/new` (alice, 200). Stale cookie: one 307 to `/signin`, then 200.
- Contrast: `#dates_extra` is `#616188` on the white modal container (about 5.9:1) once the dialog is opaque. Axe ran during the zoom fade (`opacity` on `.ant-modal` still below 1) and reported 4:1 (`#767698` on `#f5f5f6`). `ApplyLeaveModal` opens with `transitionName=""` and `maskTransitionName=""` so the dialog is fully opaque when it is shown. `web/e2e/a11y.spec.ts` was not changed. `web/src/proxy.ts` was not changed; it stays an optimistic cookie gate.
